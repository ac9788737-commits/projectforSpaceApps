# AstroCrop — симулятор роста растений на других планетах

> Этот файл — главная инструкция для Claude Code. Положи его в корень репозитория как `CLAUDE.md`.

## 1. Цель проекта

Веб-приложение — **симулятор фермера, который управляет природой**: «Что будет с культурой X, если я устрою ей вот такие условия и события?»

- **Условия задаёт пользователь.** Температура, вода, свет, воздух, почва, гравитация, УФ, радиация — ползунками, вживую или заранее.
- **События** — жара, заморозок, похолодание, засуха, ливень, град, буря, пылевая буря, вспышка звезды, затмение, сбой теплицы. **Действия фермера** — полив, удобрение, мульча, укрытие, затенение, дренаж, подвязка, сбор, пересев.
- **Планеты — стартовые миры.** Реальные (Солнечная система + экзопланеты из открытых каталогов) и гипотетические; путь «галактика → планета → огород» выбирает основу, дальше пользователь меняет что угодно. Есть и земные климаты, и «пустой мир».
- **Культуры** — овощи, зерновые, зелень, бобовые, грибы, микроводоросли; **укрытия** — открытый грунт / теплица (купол) / закрытая ферма.
- **Режимы** — Песочница, Сценарий, Эксперимент (сравнение и перебор параметра), Испытания.
- **Результат** — честная почасовая реакция растения (рост, стресс, повреждения, восстановление, гибель) и отчёт за сезон: урожай в % от нормы и от земного, что навредило и что помогло, главная причина.

Подробное ТЗ — `docs/SIMULATOR.md`.

Все исходные данные берутся из **открытых источников** и подгружаются автоматически. Каждое значение должно хранить информацию о происхождении (источник, дата загрузки, или пометка «оценка/допущение»).

## 4. Источники данных

Каждый загрузчик: скачивает → сохраняет «сырьё» в `data/raw/<источник>/<дата>` → нормализует в единые единицы СИ → пишет в БД вместе с `source`, `source_url`, `retrieved_at`.

### Планеты и звёзды
- **NASA Exoplanet Archive** — TAP API, таблица `pscomppars`.
  Нужные поля: `pl_name, pl_rade, pl_bmasse, pl_orbsmax, pl_orbper, pl_orbeccen, pl_eqt, pl_insol, st_teff, st_rad, st_mass, st_lum, st_spectype, sy_dist`.
  Пример: `https://exoplanetarchive.ipac.caltech.edu/TAP/sync?query=select+...+from+pscomppars&format=csv`
- **PHL Habitable Worlds Catalog** — CSV, используется для отметок «потенциально обитаемая».
- **Солнечная система** — курируемый `data/seed/solar_system.csv` (Меркурий…Нептун + Луна, Титан, Европа, Энцелад) по данным NASA Planetary Fact Sheet; в этом CSV указывай ссылку на источник.
- (опционально) **exoplanet.eu** — для перекрёстной проверки.

### Растения
- **FAO EcoCrop** — температурные пороги (абсолютный/оптимальный минимум и максимум), осадки, pH, продолжительность цикла. Поскольку официальный API нестабилен, используй экспорт CSV (например, данные из R-пакета `Recocrop`) и сохрани его в `data/seed/`.
- **Курируемый `data/seed/crop_physiology.csv`** — параметры, которых нет в EcoCrop: точка компенсации и насыщения по свету (PPFD), DLI, отклик на CO₂ (C3/C4), чувствительность к O₂ в корневой зоне, устойчивость к УФ, минимальное давление. Каждая строка — с полем `reference` (статья/отчёт NASA). **Если источника нет — пометка `estimate=true`, никаких выдуманных ссылок.**
- Опорные эксперименты для валидации: NASA Veggie / Advanced Plant Habitat (МКС), опыты с симулянтами марсианского/лунного реголита.

### Другие галактики
Подтверждённых экзопланет за пределами Млечного Пути практически нет (только отдельные кандидаты). Поэтому `galaxies.py` содержит **пресеты сред**: металличность, типичное распределение спектральных классов звёзд, фон космических лучей, плотность сверхновых (например: Млечный Путь, Магеллановы Облака, эллиптическая галактика, карликовая галактика, галактика со звёздообразованием). Планеты в них **генерируются** по параметрам пресета и всегда помечены `hypothetical=true`.

## 5. Модель симуляции

### 5.1 Среда (physics/)
Из параметров звезды и планеты рассчитай:
- **Гравитацию** `g = G·M/R²` (в g⊕).
- **Освещённость** на верхней границе атмосферы: из `pl_insol` или `L★ / (4π a²)`.
- **Долю PAR (400–700 нм)** — интеграл спектра Планка при `st_teff` → поток PAR (Вт/м²) → **PPFD (мкмоль/м²/с)**. Для красных карликов отдельно считай долю дальнего красного/ИК: она важна для фотоморфогенеза.
- **Длину дня / приливный захват** (эвристика по периоду орбиты и массе звезды; если не определяется — флаг `uncertain`).
- **Температуру** — равновесная температура с альбедо + парниковая поправка, если атмосфера известна; иначе диапазон.
- **Атмосферу** — давление, pCO₂, pO₂ (для экзопланет почти всегда неизвестны → пресеты: «как Земля», «как Марс», «как Венера», «плотная CO₂», «нет атмосферы»; пользователь может выбрать).
- **Радиацию** — УФ (по спектру + вспышечная активность для M-карликов), космические лучи (по наличию магнитосферы и атмосферы).

### 5.2 Сценарий (scenarios/)
Сценарий **преобразует внешнюю среду во внутреннюю**:
- **A. Открытая поверхность** — среда как есть.
- **B. Теплица** — давление ≥ заданного минимума, температура подтягивается к диапазону, свет = внешний × пропускание стекла, частичная защита от УФ. Возвращает требования к инженерии (перепад давлений, теплопотери).
- **C. Закрытая ферма** — полный контроль, LED-освещение; ограничение — только гравитация + энергобюджет (оценка кВт·ч на кг урожая).

### 5.3 Отклик растения (biology/)
Для каждого фактора — функция отклика `f_i(x) ∈ [0, 1]`:
- температура — **бета-функция кардинальных температур** (Tmin, Topt, Tmax);
- свет — насыщающая кривая (неправая гипербола) по PPFD + отдельный множитель фотопериода/DLI;
- CO₂ — отклик C3/C4;
- давление / O₂ — пороговые функции;
- гравитация — эмпирическая функция (данные микрогравитации МКС и экспериментов на центрифуге; для g > 1 — осторожная экстраполяция с пометкой низкой уверенности);
- радиация, вода, грунт (перхлораты, pH) — пороговые/линейные.

Итог:
```
yield_rel = Π f_i            # мультипликативная модель (основная)
limiting  = argmin f_i       # закон Либиха — для объяснения
survival  = все f_i выше летального порога?
```
Длительность цикла масштабируется через сумму эффективных температур (GDD) и DLI.

**Каждый результат возвращает:** `yield_rel`, `survival`, `days_to_harvest`, `factors[]` (значение, f_i, статус ok/stress/lethal), `limiting_factor`, `confidence` (high/medium/low), `assumptions[]`, `recommendations[]`.

### 5.4 Неопределённость
Если входные параметры заданы диапазоном — **Монте-Карло** (N=1000) → P10/P50/P90 урожайности. Уверенность понижается за каждое допущение и за экстраполяцию за пределы экспериментальных данных.

## 7. Фронтенд

1. **Каталог планет** — таблица с фильтрами (тип звезды, освещённость, масса, «обитаемая зона»), переключатель «реальные / гипотетические / другие галактики».
2. **Карточка планеты** — параметры с бейджами источников, спектр звезды vs спектр Солнца с полосой PAR.
3. **Симулятор** — выбор планеты, культуры, сценария, пресета атмосферы → радарная диаграмма факторов, итоговая урожайность, лимитирующий фактор, допущения, рекомендации.
4. **Сравнение** — тепловая карта «планеты × культуры».

## 8. Этапы

1. **MVP**: Солнечная система + 10 культур (салат, картофель, пшеница, томат, соя, рис, редис, шпинат, горох, спирулина) + сценарии A/B/C + симулятор через API + тесты. *Валидация: Земля → ~100% для всех культур; открытая поверхность Марса → 0 выживаемости.*
2. Загрузка NASA Exoplanet Archive + PHL, каталог, фронтенд-страницы 1–3.
3. Монте-Карло, сравнение, пресеты галактик, генератор гипотетических планет, 3D-визуализация.
4. (опционально) экспорт отчёта в PDF/CSV, пользовательские культуры.

## 9. Правила для Claude

- **Никаких выдуманных данных.** Если параметра нет в источнике — `null` + понятное допущение; ссылки на статьи — только реальные и проверяемые, иначе `estimate=true`.
- Все физические величины — через `pint` или с явными единицами в имени поля (`temp_k`, `ppfd_umol_m2_s`).
- Физика и биология — **чистые функции** без I/O, каждая покрыта юнит-тестом с проверкой на известном случае (Земля/Солнце, Марс).
- Загрузчики идемпотентны, кешируют сырые данные и не роняют приложение при недоступности источника.
- Перед крупными изменениями — короткий план; после — `make test` и `make lint`.
- Код и комментарии — на английском, UI и документация для пользователя — на русском.
- Научные допущения фиксируй в `docs/ASSUMPTIONS.md` (одна строка — одно допущение + обоснование).
