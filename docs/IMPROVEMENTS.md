# WhatCropNext — Этап 9: 13 улучшений + надёжный снимок поля

> Положи файл в `docs/IMPROVEMENTS.md`. Действуют правила из `CLAUDE.md`, `docs/DESIGN.md`, `docs/ROTATION.md`, `docs/UX.md` (в том числе: простой язык на основных экранах, реакция конструктора < 500 мс, ни одного числа без источника или пометки «оценка»).

## Часть A. Снимок поля: всегда, быстро, без токенов

### A.1 Почему снимки «то грузятся, то нет»
1. Сервис требует токен или режет по лимитам.
2. Попался облачный день — вместо поля белое пятно.
3. Скачивается целая сцена (сотни МБ) вместо маленького квадрата вокруг поля.

### A.2 Каскад из трёх уровней + кеш
Бэкенд пробует уровни по очереди, у каждого — **жёсткий таймаут**. Пользователь всегда получает картинку; в углу снимка плашка, какой уровень сработал и дата съёмки.

**Уровень 1 — свежий снимок Sentinel-2, 10 м, + карта NDVI (без ключей).**
- STAC-каталог **Element84 Earth Search** `https://earth-search.aws.element84.com/v1`, коллекция Sentinel-2 L2A (предпочтительно `sentinel-2-c1-l2a`, иначе `sentinel-2-l2a`). Файлы — Cloud-Optimized GeoTIFF на AWS Open Data, доступ без авторизации.
- `pystac-client` → поиск сцен по bbox поля за последние 60 дней, `eo:cloud_cover < 30`, сортировка по дате.
- **Облачность проверять по самому полю, а не по сцене:** для 3–5 кандидатов прочитать слой классификации сцены (SCL, 20 м) только в окне поля и посчитать долю облаков/теней. Взять самый свежий снимок с облаками над полем < 5 %.
- `rasterio` windowed read строго по bbox поля + отступ 20 %, с перепроекцией полигона из WGS84 в UTM сцены. Каналы B04/B03/B02 → true color (растяжка + гамма), B08/B04 → NDVI с цветовой шкалой. Отдать PNG/WebP + контур поля + дату.
- Переменные GDAL для скорости: `AWS_NO_SIGN_REQUEST=YES`, `GDAL_DISABLE_READDIR_ON_OPEN=EMPTY_DIR`, `CPL_VSIL_CURL_ALLOWED_EXTENSIONS=.tif`, `GDAL_HTTP_MULTIPLEX=YES`, `VSI_CACHE=TRUE`.
- Чтения кандидатов — параллельно, общий таймаут уровня 4 с.
- Атрибуция (обязательно, под снимком): «Contains modified Copernicus Sentinel data [год]».

**Уровень 2 — безоблачная мозаика (тайлы, мгновенно).**
- Тайлы через WMTS/XYZ без ключа, например **NASA GIBS** (дневные снимки MODIS/VIIRS — грубее, но это NASA и всегда доступно) и/или безоблачная мозаика Sentinel-2 **EOX Sentinel-2 cloudless** (проверь лицензию конкретного года мозаики и укажи атрибуцию в `docs/CREDITS.md`).
- Без NDVI-карты, плашка «Мозаика, не свежий снимок».

**Уровень 3 — локальная заглушка, которая не может не загрузиться.**
- Для демо-полей — заранее сохранённые снимки и NDVI в `frontend/public/demo/imagery/` (делает `make precompute`).
- Для любого поля — схематичная подложка: контур поля поверх стилизованной карты рельефа (SRTM) или нейтрального фона + «Снимок временно недоступен, данные анализа не зависят от него».

**Кеш (перед всеми уровнями).**
- Ключ: хеш bbox + уровень + неделя. Хранить PNG и метаданные (дата, облачность, уровень, источник).
- Для демо-полей всё лежит в кеше заранее, поэтому на показе снимок **гарантированно** появляется < 0.5 с.
- Честное ожидание для нового поля: уровень 1 обычно 1–4 с (на бесплатном сервере с 0.1 CPU — ближе к верхней границе), уровни 2–3 — мгновенно. Пока идёт уровень 1, сразу показывать уровень 2, потом плавно заменить на свежий снимок.

### A.3 Где показывать
- Экран 1: снимок + контур поля в «паспорте поля»; переключатель «Фото / Зелень (NDVI)».
- Подсказка простым языком: «Чем зеленее на карте зелени, тем больше живых растений. Снимок от 3 ноября 2026, спутник Sentinel-2».
- API: `GET /fields/{id}/imagery?kind=truecolor|ndvi` → `{url, date, level, cloud_pct, source, attribution}`.

### A.4 Тесты
- Мок STAC/COG: облачная сцена над полем отбрасывается даже если общая облачность сцены низкая.
- Таймаут уровня 1 → возвращается уровень 2; недоступен уровень 2 → уровень 3. Ответ всегда 200 с картинкой.
- Перепроекция: известный полигон → правильное окно в пикселях.
- Демо-поля работают без сети.

## Часть B. 13 улучшений

### Экран 1 — «Какое у вас поле?»

**B1. Тренд «Тогда и сейчас».** В паспорте поля для жарких дней, осадков и заморозков — одна строка сравнения двух половин периода:
«Жарких дней (> 35 °C): было 64 в 2005–2014, стало 88 в 2015–2024 (+38 %)». Числа — из того же ряда NASA POWER. Если разница в пределах обычных колебаний год к году — писать «почти без изменений», а не раздувать тренд (простой тест: разница средних больше половины стандартного отклонения, иначе «без заметных изменений»).

**B2. Полив до старта.** При выборе/рисовании поля — три кнопки-пилюли: **«Без полива (богара)» / «Полив по бороздам» / «Капельный полив»**. Для демо-полей — значение по умолчанию из описания поля. Влияет на: доступную воду, эффективность полива (борозды ниже, капельный выше — коэффициенты с источником), затраты, риск засоления (B8). Без полива культуры, которые здесь без воды не вырастут, помечаются в колоде «нужен полив».

### Экран 2 — «Что сеять?»

**B3. Траектория по годам.** Под таймлайном — тонкий мини-график «Запас почвы» (органика + азот, нормированные в один понятный показатель 0–100) по точкам Год 0 → Год 4 с зелёной/жёлтой/красной зонами. Монокультура — линия ползёт вниз, с бобовыми и покровными — вверх. Наведение → «Год 3: азот 38 кг/га, органика 1.1 %». Обновляется вместе с индикаторами.

**B4. Азот в деньгах.** На стрелке-связи после бобовых: «Нут в 1-й год → во 2-й год нужно на 40 кг/га меньше азотных удобрений (экономия ≈ $55/га)». Килограммы — из модели азота, цена — из таблицы цен поля (меняется на экране 3, B10). Эта экономия уже входит в маржу индикатора «Деньги».

**B5. Живые титры.** Во время «▶ Прожить 4 года», «🎲 Кубик погоды» и в мини-полях «20 лет» — всплывающие события поверх поля в момент события:
«Год 2, июль: +39 °C на цветении — урожай −28 %», «Год 3, март: ливень 45 мм, вика удержала почву».
- Генерируются из журнала событий модели (порог: событие изменило урожай/почву/воду заметно, например > 5 %), а не придумываются.
- Не больше одного титра за 1.5 с, самые важные — крупнее. Пауза по клику на титр.
- После проигрывания — список всех титров в свёрнутом журнале.

**B6. Защита от «читерских» схем.** В карточке культуры и в 4 индикаторах учитывать:
- **стартовые затраты, $/га** (семена, посадочный материал, удобрения, работы) и **ручной труд, чел.-дней/га**;
- в анкете — бюджет на сезон и доступные рабочие руки;
- индикатор «Деньги» показывает и маржу, и «нужно вложить в начале сезона»;
- «✨ Подобрать лучший план» не предлагает схем, которые превышают бюджет или труд; при ручной сборке превышение — жёлтая рамка «Нужно $1 400/га на старте — больше вашего бюджета»;
- правило по умолчанию: не больше одной очень дорогой/трудоёмкой культуры за цикл (настраивается).

**B7. Исправление в 1 клик.** Рядом с красной/жёлтой рамкой — чипы «Чем заменить? → Нут / Кукуруза». Варианты — 2–3 культуры, которые снимают нарушение и лучше всего по приоритетам фермера (быстрый пересчёт). Клик → замена с анимацией, индикаторы обновляются.

### Агрономия засушливых и орошаемых полей

**B8. Риск засоления.** Без сложной солевой модели — понятный триггер: поле с поливом + тяжёлая почва (высокая доля глины по SoilGrids) + высокая испаряемость (из NASA POWER, FAO-56) + большой объём полива/плохой дренаж → жёлтая плашка: «Риск засоления: проверьте дренаж; помогут промывка, капельный полив и глубококорневые культуры». Пороги — в `data/seed/salinity_rules.csv` с источниками или пометкой «оценка». Обязательно попадает в «Что проверить на месте». На поле в 3D — белёсый налёт (см. `UX.md` §4).

**B9. Срок заделки покровной культуры.** Если после зимней покровной культуры идёт летняя на поле без полива или с дефицитом воды — строка на карточке и в плане: «Заделать вику за 2–3 недели до сева хлопка, чтобы она не забрала весеннюю влагу». В модели: покровная культура расходует воду до даты заделки; дата заделки по умолчанию = сев следующей культуры минус 14–21 день (настраивается в режиме эксперта). Если поставить позже — модель честно покажет потерю влаги.

### Экран 3 — «Ваш план»

**B10. Местные цены за 0 мс.** На итоговом экране — 2–4 ползунка/поля «Цена у вас на рынке» для культур плана (+ цена азотного удобрения и воды). Урожай в т/га уже посчитан, поэтому маржа пересчитывается **в браузере** без запроса к серверу. Кнопка «Вернуть мировые цены 2024». Новые цены сохраняются для поля и используются в конструкторе.

**B11. Календарь работ на 1-й год.** Полоса 12 месяцев: окно сева → критический период (полив/жара) → уборка → посев покровной → заделка покровной. Даты — из модели и истории заморозков/жары поля. Есть на экране и в PDF.

### Для судей и режима эксперта

**B12. Языки RU / EN (+ TJ для названий культур).** Переключатель в шапке, `react-i18next`, все строки интерфейса — в `frontend/src/i18n/{ru,en,tg}.json` (никакого текста, зашитого в компоненты). Таджикский — минимум названия культур и главные кнопки. Титры (B5), подсказки и PDF тоже переводятся. Автотест: в каждом языке нет пропущенных ключей.

**B13. Справочник «Откуда цифры».** В режиме эксперта — одна таблица всех культур: семейство, Kc по стадиям (FAO-56), T_opt и порог жары (EcoCrop), фиксация азота, глубина корней, затраты и труд, **источник или пометка «оценка»** для каждого значения. Поиск, сортировка, экспорт CSV. Ссылка «ⓘ Откуда цифры» с любого индикатора ведёт в нужную строку.

## Часть D. Критерии готовности

- Для каждого демо-поля снимок и NDVI появляются < 0.5 с без сети; для нового поля картинка (хотя бы уровень 2) — < 1 с, свежий снимок — обычно < 4 с.
- Отключение интернета у бэкенда не ломает ни один экран.
- Монокультура хлопка на демо-поле Таджикистана: линия «Запас почвы» идёт вниз, появляется предупреждение о засолении (если почва тяжёлая и полив по бороздам); замена через чип на нут поднимает линию и показывает экономию удобрений в $.
- «✨ Подобрать лучший план» при бюджете $300/га не предлагает схем дороже.
- Изменение цены пшеницы на экране 3 меняет маржу без сетевого запроса (проверить в DevTools).
- Переключение RU/EN меняет весь интерфейс, включая титры и PDF.
- В справочнике у каждого параметра есть источник или пометка «оценка».
