# WhatCropNext — Этап 6: симулятор фермера, управляющего природой

> Положи файл в `docs/SIMULATOR.md`. Правила из `CLAUDE.md` (данные без выдумок, тесты, коммиты, автономный режим), `docs/INTERACTIVE.md` и `docs/DESIGN.md` продолжают действовать.
> **Этот этап меняет главную логику проекта**, поэтому в начале `CLAUDE.md` обнови раздел «Цель проекта» по §1 ниже.

## 1. Новая идея

Раньше условия выращивания **вычислялись** из параметров планеты. Теперь **условия задаёт сам пользователь**: он становится фермером, который управляет природой.

- Можно выставить любую температуру, влажность, свет, ветер, осадки и т.д.
- Можно «насылать» события: жару, заморозок, засуху, ливень, град, бурю, пылевую бурю, вспышку звезды…
- Можно делать это **заранее** (расписать сценарий на сезон) или **вживую** (менять условия, пока растение растёт).
- Симулятор честно показывает, как культура реагирует: растёт, болеет, гибнет, восстанавливается, сколько даёт урожая.

**Планеты не исчезают — они становятся стартовыми мирами.** Пользователь выбирает основу (Земля — конкретный климат, Марс, Луна, экзопланета или «пустой мир»), и её параметры становятся начальными значениями. Дальше он может изменить что угодно. Путь «галактика → планета → огород» остаётся способом выбрать стартовый мир.

## 2. Режимы

| Режим | Что делает пользователь | Зачем |
|---|---|---|
| **Песочница** | Выбирает мир, сажает культуры, крутит ползунки и насылает события в любой момент | Свободная игра и исследование |
| **Сценарий** | Заранее расставляет события на таймлайне сезона, жмёт ▶ и смотрит | Воспроизводимый эксперимент «что будет, если…» |
| **Эксперимент** | Сравнивает: одна культура при двух-четырёх наборах условий бок о бок, или перебирает параметр (например температуру от 5 до 40 °C) и получает график «урожай от параметра» | Научный режим |
| **Испытания** | Готовые задания: «Собери 3 кг картофеля, пережив 10-дневную засуху», «Вырасти салат на Марсе, используя не больше 2 вмешательств», «Спаси пшеницу от заморозка во время цветения» | Игровой режим, обучение |

## 3. Чем управляет пользователь

### 3.1 Условия среды (ползунки)
Каждое значение: **базовое** (из стартового мира) → **пользовательское** (переопределение). Для каждого ползунка показывается зона оптимума выбранной культуры (зелёная полоса).

| Группа | Параметры |
|---|---|
| Температура | дневная и ночная температура воздуха, температура почвы |
| Вода | осадки (мм/сутки), влажность воздуха, влажность почвы, уровень грунтовых вод |
| Свет | интенсивность (PPFD), длина дня (фотопериод), спектр (тёплый / солнечный / красный карлик / LED), облачность |
| Воздух | CO₂ (ppm), O₂, давление, скорость ветра |
| Почва | тип (песок / суглинок / глина / реголит), pH, питательные вещества (N/P/K условно: низко / норма / высоко), солёность |
| Космос | гравитация, УФ, радиационный фон |

### 3.2 События (карточки)
Событие — это изменение условий **на ограниченное время** с плавным началом и концом. У каждого события: **сила** (слабо / средне / сильно или число), **длительность**, **момент начала**.

| Событие | Что меняет | Чем опасно |
|---|---|---|
| Волна жары | +T днём и ночью, ↓ влажность | тепловой стресс, стерильность при цветении, остановка клубнеобразования |
| Заморозок | T ниже 0 °C ночью на N часов | повреждение и гибель тканей |
| Долгое похолодание | ↓T на дни/недели | замедление роста |
| Засуха | осадки = 0, ↑ испарение | водный стресс, увядание |
| Ливень / наводнение | много осадков, почва переувлажнена | гипоксия корней, гниль |
| Град | механическое повреждение | потеря листьев/плодов |
| Буря | сильный ветер | полегание, обломанные стебли |
| Пылевая буря (Марс) | ↓ свет на дни/недели | нехватка света |
| Вспышка звезды | всплеск УФ/радиации | повреждение листьев |
| Затмение / долгая ночь | свет = 0 на N часов | голодание |
| Тепличный сбой (если есть купол) | потеря давления / подогрева | резкий переход к внешним условиям |

Позже (опционально): вредители и болезни, вероятность которых растёт при определённых условиях (тепло + влажность → грибковые болезни).

### 3.3 Действия фермера
Помимо управления природой, есть обычные агро-действия (расходуют «очки вмешательства» в режиме испытаний):
полив, удобрение, мульчирование, укрытие от заморозка (агроволокно), затенение, дренаж, подвязка, сбор урожая, пересадка/пересев.

## 4. Изменения в движке симуляции

Движок становится **пошаговым и с памятью**: раньше среда была почти статичной, теперь она меняется каждый час, а растение накапливает повреждения и может восстанавливаться.

### 4.1 Структура
```
backend/app/sim/
├── environment/
│   ├── base_climate.py      # базовый суточный и сезонный ход из стартового мира
│   ├── overrides.py         # переопределения пользователя
│   ├── events.py            # события: функции env(t) с плавным началом и концом
│   └── compose.py           # base → overrides → events → actions → итоговая среда на шаг
├── plant/
│   ├── state.py             # PlantState: стадия, биомасса по органам, вода, повреждения, здоровье
│   ├── phenology.py         # смена стадий (сумма эффективных температур, фотопериод)
│   ├── growth.py            # прирост биомассы (использование света), распределение по органам
│   ├── water.py             # водный баланс почвы (простая «корзина»), испарение, увядание
│   └── damage.py            # заморозок, жара, гипоксия, ветер/град, радиация; восстановление
├── soil.py
├── actions.py               # действия фермера
├── engine.py                # шаг симуляции: env(t) → отклик растения → новое состояние
└── session.py               # живая сессия: состояние, пауза, изменения на лету
```

### 4.2 Правила модели
- **Шаг — 1 час** (иначе не поймать ночной заморозок), отчёт для UI — по суткам + все события.
- **Чувствительность зависит от стадии.** Одинаковая жара на вегетации и во время цветения даёт разный эффект; таблица чувствительности по стадиям — в `data/seed/crop_stage_sensitivity.csv` с источниками.
- **Повреждения накапливаются** (например, часы ниже порога заморозка) и частично восстанавливаются, если условия вернулись в норму. Необратимые повреждения (гибель листьев, стерильность цветков) не восстанавливаются.
- **Гибель растения** — когда здоровье падает до 0 или повреждена точка роста.
- **Детерминизм:** одинаковые входные данные + одинаковый `seed` → одинаковый результат.
- Все пороги и коэффициенты культур — в seed-CSV с колонкой `reference`; если источника нет — `estimate=true`, и в UI это видно.

### 4.3 Живая сессия (реальное время)
Пользователь меняет условия во время проигрывания, поэтому симуляция идёт сессией:

```
POST   /sim/sessions                   {world, crops[], overrides, scenario_events[], seed} → session_id
WS     /sim/sessions/{id}/stream       сервер шлёт кадры: {day, hour, env, plants[], events_fired[]}
POST   /sim/sessions/{id}/control      play / pause / speed / seek (назад — пересчёт от начала с тем же seed)
PATCH  /sim/sessions/{id}/conditions   изменить ползунки на лету
POST   /sim/sessions/{id}/events       наслать событие сейчас или запланировать
POST   /sim/sessions/{id}/actions      действие фермера
GET    /sim/sessions/{id}/report       итоговый отчёт
POST   /sim/batch                      режим эксперимента: перебор параметров → таблица результатов
```

Сессию нужно уметь сохранить как **сценарий** (JSON) и загрузить снова. Всё, что пользователь сделал вживую, записывается в журнал, поэтому любую сессию можно точно воспроизвести.

### 4.4 Формат сценария
```json
{
  "version": 1,
  "world": "earth:temperate",          // или "mars", "exo:TRAPPIST-1 e", "blank"
  "seed": 42,
  "duration_days": 120,
  "crops": [{"crop": "potato", "plot": "A1", "protection": "open"}],
  "overrides": {"temp_day_c": 22, "temp_night_c": 12, "co2_ppm": 800},
  "events": [
    {"type": "heatwave", "start_day": 45, "duration_days": 7, "intensity": "strong"},
    {"type": "frost", "start_day": 90, "duration_hours": 6, "min_temp_c": -4}
  ],
  "actions": [{"type": "irrigate", "day": 50, "mm": 20}]
}
```
Сценарии можно делиться ссылкой (сценарий кодируется в URL или сохраняется с коротким id).

## 5. Интерфейс

Огород из этапа 5 остаётся центром, вокруг него появляется пульт управления природой (стиль — из `DESIGN.md`, настроение `garden`).

- **Левая панель «Природа»** — вкладки: Температура / Вода / Свет / Воздух / Почва / Космос. Ползунки с зоной оптимума культуры, кнопка «↺ вернуть как в мире».
- **Колода событий** снизу справа: карточки событий. Карточку можно **кликнуть** — событие начнётся сейчас, или **перетащить на таймлайн** — событие запланируется.
- **Таймлайн сезона** (расширенная панель времени): дорожка событий (цветные отрезки, которые можно тянуть и растягивать), под ней графики температуры, осадков и света, линия «сейчас».
- **Прогноз** — полоска на ближайшие 7 дней с иконками погоды (с учётом запланированных событий).
- **Правая панель «Растение»** — здоровье, стадия, урожай (сейчас / прогноз), активные стрессы с причинами («Жара 38 °C во время цветения → −30% завязей»).
- **Панель фермера** — кнопки действий (полив, укрытие и т.д.).
- **Режим «Эксперимент»** — экран делится на 2–4 огорода с одинаковыми культурами и разными условиями, время у всех синхронное; под ними сравнительные графики. Для перебора параметров — отдельный экран с графиком «урожай от параметра».
- **Итоговый отчёт** после сезона: урожай, график здоровья, что навредило сильнее всего, что помогло, кнопки «Повторить с изменениями» и «Сохранить сценарий».

### Визуализация погоды в 3D
Каждое условие должно быть **видно в сцене**:
- дождь, ливень, лужи, вода на грядках при переувлажнении;
- снег и иней на листьях при заморозке;
- марево (шейдер искажения воздуха) при жаре, выцветшее небо;
- град — отскакивающие льдинки, сбитые листья;
- ветер — растения клонятся сильнее, летит пыль/листья;
- облачность и пылевая буря — свет темнеет, небо меняет цвет;
- вспышка звезды — короткая яркая засветка;
- ночь, затмение — смена освещения, звёзды.
Реакция растения — как в `INTERACTIVE.md` §4 (поникание, пожелтение, вытягивание и т.д.), но теперь ещё и в динамике: растение вянет в засуху и **оживает после полива**.

## 6. Порядок работы

1. **6.1** Движок: пошаговая модель с шагом 1 час, водный баланс, повреждения и восстановление, события, детерминизм. Тесты (§7).
2. **6.2** Сценарии: формат JSON, сохранение и загрузка, режим «Сценарий» без UI (через API) + отчёт.
3. **6.3** Живая сессия: WebSocket, изменения на лету, журнал, перемотка назад через пересчёт.
4. **6.4** UI: панель «Природа», колода событий, таймлайн с перетаскиванием, прогноз, панель растения.
5. **6.5** Погода в 3D и динамическая реакция растений.
6. **6.6** Действия фермера, режим «Эксперимент» (сравнение и перебор параметров), итоговый отчёт.
7. **6.7** Испытания: 5–7 готовых заданий, сохранение прогресса.
8. Обнови `README.md` и раздел «Цель проекта» в `CLAUDE.md`.

## 7. Тесты и критерии готовности

Обязательные тесты движка (числовые пороги брать из источников в seed-CSV, а не из этого файла; ниже — ожидаемое **направление** эффекта):
- Без событий и с условиями «Земля, умеренный климат» результат совпадает с прежним `/simulate` (в пределах допуска).
- Короткий заморозок ниже порога культуры повреждает ботву картофеля; несколько часов сильного мороза её убивают.
- Жаркие ночи заметно снижают образование клубней картофеля по сравнению с прохладными.
- Жара во время цветения пшеницы или томата снижает урожай сильнее, чем такая же жара на вегетации.
- Засуха снижает урожай; полив во время засухи частично восстанавливает его.
- Переувлажнение на несколько дней вызывает повреждение корней.
- Одинаковый сценарий + `seed` → побайтово одинаковый отчёт.
- Перемотка назад и повторное проигрывание дают тот же результат, что и непрерывное проигрывание.

Сквозной путь, который должен работать мышкой без перезагрузки страницы:
> Выбрать «Земля, умеренный климат» → посадить картофель → нажать ▶ → на 40-й день перетащить «Волна жары» на таймлайн → увидеть марево и вянущий куст → полить → куст оживает → на 90-й день заморозок → иней на листьях → конец сезона → отчёт «урожай 62% от нормы, главная причина — жара во время клубнеобразования» → «Повторить с изменениями».

После каждого подэтапа: тесты, линтер, скриншоты Playwright по чек-листу из `DESIGN.md` §12, коммит, запись в `docs/PROGRESS.md`.
