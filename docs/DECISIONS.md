# Решения, принятые автономно

- **Git не используется.** По указанию пользователя нет ни `git init`, ни коммитов. Файл `.gitignore` создан заранее, он ни на что не влияет.
- **Корень репозитория.** Папки `backend/`, `frontend/`, `data/` лежат прямо в `projectForSpaceAp/`, это и есть `astrocrop/` из ТЗ.
- **Python 3.12 через uv.** В системе Python 3.14, проект закреплён на `>=3.12,<3.13`.
- **PHL.** Старый адрес CSV отдавал 404. Рабочий адрес `https://www.hpcf.upr.edu/~abel/phl/hwc/data/hwc.csv` взят со страницы каталога.
- **EcoCrop.** В `data/seed/ecocrop.csv` лежит полная таблица из R-пакета Recocrop (`inst/parameters/ecocrop.rds`). Выбраны строки: Lettuce, Potato, «Wheat, common», Tomato, Soyabean, «Rice paddy (Japonica)», «Radish, Western», Spinach, Pea.
- **Спирулины нет в EcoCrop.** Все её параметры заданы как оценка.
- **Научные ссылки.** В файлы попали только DOI, подтверждённые через Crossref. Значения физиологии культур не привязаны к статьям, поэтому `reference` пустой и `estimate=true`.
- **Лучший участок планеты.** Симуляция считает культуру на наиболее подходящем участке, иначе условие «Земля ≈ 100 %» невыполнимо для всех культур при средней 15 °C.
- **Температурный отклик с плато.** Бета-функция применена с плоской вершиной на оптимальном диапазоне EcoCrop.
- **Уровни уверенности.** high при счёте ≥ 0,8, medium при ≥ 0,45, иначе low; каждое допущение снижает счёт на свой штраф.
- **Газовые гиганты и Венера в закрытой ферме.** Расчёт выполняется по ТЗ («только гравитация и энергия»), но помечается `feasible=false` с понижением уверенности, чтобы не вводить в заблуждение.
- **Перехват отсутствующих данных.** Неизвестные параметры остаются `null`; расчёт либо добавляет допущение, либо возвращает 422.
- **Загрузка при старте только из локальных файлов.** Запуск не зависит от сети: кэш `data/raw`, затем снимок `data/seed/exoplanets_snapshot.csv` (70 реальных планет из пересечения NASA и PHL).
- **Каталог: вкладки.** «Гипотетические» — пресет Млечного Пути, «Другие галактики» — остальные пресеты.
- **Защита `POST /ingest`.** Требуется заголовок `X-Admin-Token`, равный `ASTROCROP_ADMIN_TOKEN`; без переменной эндпоинт отключён.
- **shadcn/ui.** Компоненты написаны вручную по его паттернам (cva + tailwind-merge) в одном файле, без интерактивного CLI; `select` нативный.
- **Клиент API.** Типы генерируются `openapi-typescript` из `frontend/openapi.json` (`make openapi`), запросы идут через `openapi-fetch`.
- **Версии фронтенда.** Vite 7 и `@vitejs/plugin-react` 5 из-за требований к peer-зависимостям; Recharts 2.
- **Сборка Docker при медленной сети.** В `backend/Dockerfile` для pip и uv увеличены тайм-ауты и число повторов, uv скачивает не больше двух файлов одновременно.
- **Необязательное не делалось.** Этап 4 и перекрёстная проверка по exoplanet.eu вне заданных этапов 1–3.

## Этап 5
- **Коммиты из `docs/INTERACTIVE.md` не делаются.** Запрет на git от пользователя действует; вместо коммита после подэтапа — тесты, линтер и запись в `docs/PROGRESS.md`.
- **Морфология отдельным CSV.** Таблица `crop_morphology.csv` читается напрямую, без новых колонок в БД, чтобы не требовать миграции существующей базы.
- **События не входят в сверку с `/simulate`.** Без событий таймлайн совпадает с `/simulate` до 1e-9; с бурями и вспышками урожай может быть только ниже, ответ содержит оба числа (`yield_rel` и `static_yield_rel`).
- **Поля `PlantState` в camelCase** (`heightM`, `organCount`…), как в ТЗ; остальные поля API — snake_case.
- **Кеш таймлайна** — LRU на 256 ответов по SHA-256 тела запроса, сбрасывается при `POST /ingest`.
- **Единица суток:** `sol` для Марса, `earth_day` для тел с очень длинными сутками, иначе `local_day`.
- **Координаты звёзд из PHL.** NASA Exoplanet Archive отвечал 503 (обслуживание), поэтому RA/Dec взяты из кэшированного каталога PHL; у каждой звезды записан источник координат (`coords_source`). Значения из NASA при следующей загрузке имеют приоритет.
- **Миграция базы.** Новые необязательные колонки добавляются при старте (`ALTER TABLE ... ADD COLUMN`), без отдельного инструмента миграций.
- **Свои гипотетические системы у M31 и ММО.** Пресеты повторяются (M31 — как Млечный Путь, ММО — как БМО), поэтому для них генерируются отдельные наборы с другим `seed` (2001 и 1001).
- **Вердикт «можно ли вырастить».** Лучшая из 10 культур в каждом сценарии; «да» при урожае ≥ 30 % и технически возможном сценарии; порядок предпочтения: открытый грунт → купол → ферма.
- **Один Canvas и перелёты.** Все уровни рендерятся в одном Canvas; переход = полёт камеры к объекту → затемнение → смена уровня → отлёт камеры. Страница не перезагружается.
- **Свои 3D-подписи вместо `drei <Html>`.** `<Html>` создаёт отдельные React-корни и в React 19 падал с `removeChild` при смене уровня; подписи теперь рендерятся в общем DOM-слое и проецируются каждый кадр.
- **Процедурные текстуры вместо карт NASA.** Все ассеты генерируются кодом (палитры тел Солнечной системы подобраны вручную), поэтому вопросов лицензий и скачивания нет; см. `docs/CREDITS.md`.
- **Шаг таймлайна = местные сутки**, кроме тел с сутками длиннее 48 ч и приливного захвата — там земные сутки (подпись «День N (земные сутки)»).
- **Плотность посадки.** 5×5 растений на грядку (225 на огород) при высоком качестве, 3×3 при низком.
- **Ускоренная перемотка не мигает.** При 5 и 20 сут/с свет фиксируется на утреннем положении звезды; при 1 сут/с виден суточный ход.
- **Dev-сервер для проверок на порту 8001**, потому что запущенные Docker-контейнеры занимают 8000; в dev-режиме камера и сцена доступны в `window.__astro` для автотестов.

## Дизайн-система (docs/DESIGN.md)
- **Коммиты из §12 не делаются**: запрет на git действует.
- **Tailwind 4 без `tailwind.config.ts`.** Токены лежат в `frontend/src/styles/tokens.css` и подключаются к утилитам через `@theme` в `index.css` (в Tailwind 4 это замена конфигу).
- **Плавная смена настроения.** Цветовые токены и радиусы зарегистрированы через `@property`, поэтому `data-mood="space"` → `"garden"` анимируется 600 мс одним CSS-переходом.
- **Кириллица в заголовках.** У Space Grotesk нет кириллицы; в стеке заголовков вторым идёт Manrope (OFL, с кириллицей и похожей геометрией): латиница — Space Grotesk, кириллица — Manrope.
- **Непрозрачность стекла 0,86 вместо 0,72/0,70.** Иначе вторичный и статусный текст не держит 4,5:1 на самых светлых фонах сцены (ядро галактики, горизонт Земли, небо Марса) — §11 разрешает усилить непрозрачность.
- **Текстуры планет.** Карты Солнечной системы — Solar System Scope (CC BY 4.0, на основе данных NASA), см. `docs/CREDITS.md`; Титан, Европа, Энцелад и экзопланеты — процедурные.
- **Цвета сцены из токенов.** 3D-материалы читают CSS-переменные (`explore/lib/tokens.tsx`); цвета звёзд — из `utils/blackbody.ts`, неба и грунта — из данных среды.
- **Поправка прозрачности при постобработке.** С EffectComposer полупрозрачные линии и кольца смешиваются в линейном пространстве и выглядят ярче; для них используется `alpha^2,2`, чтобы оба режима качества выглядели одинаково.
- **Боковые панели на ширине < 1280 px свёрнуты по умолчанию** (центр сцены свободен); на телефоне обе панели — вкладки одной шторки, главное действие (▶, «Высадиться») — в нижней зоне.
- **Пробел в огороде** всегда переключает ▶/⏸, даже если фокус на кнопке (кнопки нажимаются клавишей Enter); поля ввода, ползунки и выпадающие списки пробел не теряют.
- **Карточки объектов** открываются в сторону от ближайшей боковой панели и вверх в нижней половине экрана, чтобы не закрывать главный объект.
- **Ночь в огороде не чёрная**: стилизованный минимум света (звёзды/земной свет), реальная освещённость — в панели. Правило §6.4: картинку стилизуем, цифры — нет.
- **Палитра статусов** (`--ok/--stress/--lethal`) проверена валидатором dataviz: худшая пара при дальтонизме ΔE 8,7 (протанопия), нормальное зрение 18,7, контраст на фоне ≥ 3:1; статус всегда дублируется иконкой и текстом.

## Этап 6. Симулятор фермера
- **Без git.** ТЗ просит коммит после каждого подэтапа, но пользователь запретил что-либо отправлять в git; коммитов нет, прогресс — в `docs/PROGRESS.md`.
- **Новый движок `backend/app/sim/`, старый `/simulate` не тронут.** Таблицы и сравнение по-прежнему используют прежний расчёт; без событий и переопределений новый движок даёт те же цифры (Марс в куполе и на ферме — совпадение; Земля при тех же температурах площадки — расхождение не больше 0,02 доли урожая; это проверяют тесты).
- **Живая сессия = журнал изменений + полный пересчёт.** Каждое изменение (ползунок, событие, действие) пишется в журнал с моментом времени; траектория пересчитывается целиком. Сезон дешёвый (≈ 2600 часов), зато перемотка назад точна и сезон с тем же журналом и зерном воспроизводится байт в байт.
- **Часы на сервере, кадры по WebSocket ~10 раз в секунду**; клиент между кадрами экстраполирует время сам, поэтому анимация плавная. Перемотка ползунком меняет день сразу, не дожидаясь кадра.
- **Сутки начинаются в полночь, как в движке**; новый сезон открывается утром первого дня (9:00), чтобы сцена не стартовала в темноте. Солнце в 3D теперь идёт по часам движка (раньше граница суток была в полдень).
- **Эксперимент считается без живой сессии**: варианты — отдельные сценарии, часы локальные; события и действия в этом режиме не доступны.
- **Колода событий встроена в таймлайн** (кнопка «События» в его шапке, колода всплывает над ним). Отдельный угол на экране перекрывал таймлайн и действия фермера. На высоких экранах (≥ 1000 px) колода открыта сразу, на остальных сворачивается после использования.
- **Ниже 1400 px боковые панели заканчиваются над таймлайном** (высота нижней зоны передаётся через CSS-переменную); шире — таймлайн сужается до промежутка между панелями.
- **Испытания проверены расчётом**: каждое выполнимо разумной стратегией и не выполняется «само». «Томаты в жару» — жара перенесена на цветение (40-е сутки): без действий 5 %, с тремя затенениями 62 % при цели 50 %. «Ливень на глине» — глина и капельный полив, цель 85 % от нормы: без дренажа 81 %, с дренажом 87 %.
- **Заморозок без заданной длительности, начатый днём, длится до утра**: иначе карточка «сейчас» в полдень почти ничего не делала, ведь мороз бывает ночью.
